Create `src/generators/llmGenerator.js` as an ESM module (no `require`, use `import`). Zero new npm dependencies — only Node.js builtins (`fs`, `path`). `fetch` is global in Node 18+ (no import needed).

**Structure the file in this order:**

1. **Imports** (Node.js builtins only):
```javascript
import { readFileSync, writeFileSync } from 'fs'
import { posix } from 'path'
```

2. **Constants**:
- `API_URL = 'https://models.github.ai/inference/chat/completions'`
- `SYSTEM_PROMPT` (multi-line template literal per RESEARCH.md system prompt structure)
- `MODEL_LIMITS` object with 6 entries from interfaces above, default 32_000 for unknown models
- `DELIMITER_RE = /^=== FOLDER:\s*(.+?)\s*===$/m`

3. **`export function estimateTokens(text)`**:
- Split on `/\s+/`, filter empty strings, divide by 0.75, Math.ceil
- Returns a number

4. **`export function parseResponse(responseText, expectedFolderPaths)`**:
- Split responseText on DELIMITER_RE: `responseText.split(DELIMITER_RE)`
- The split alternates: `['', 'src/services', 'content...', 'src/controllers', 'content...']`
- Build a Map<string, string> where key=folderPath (trimmed), value=content (trimmed)
- After building the Map, validate that every path in expectedFolderPaths is present in the Map
- If any expected path is missing: `throw new Error(\`LLM response missing content for folder: \${missingPath}\`)`
- If content for a found path is empty/whitespace: `throw new Error(\`LLM returned empty content for folder: \${path}\`)`
- Return the Map

5. **`export async function generateLLMInstructions(generatedPaths, folders, options)`**:
- `const { llmModel, verbose = true } = options`
- Log: `console.log(\`  Sending \${generatedPaths.length} folders to LLM (\${llmModel})...\`)`
- Build userPrompt: for each path in generatedPaths, read file with readFileSync, prepend `=== FOLDER: <relativePath> ===` delimiter. The relativePath should come from the corresponding folder object in folders[] — normalize to posix (forward-slash) using `posix.normalize`
- Concatenate all sections into one string
- Estimate tokens of `SYSTEM_PROMPT + userPrompt`
- Enforce token budget: get limit from MODEL_LIMITS[llmModel] ?? 32_000; if estimate > limit, `console.error(...)` and `process.exit(1)`
- Call the GitHub Models API via global `fetch`:
  - POST to API_URL
  - Headers: `Authorization: Bearer ${process.env.GITHUB_TOKEN}`, `Content-Type: application/json`
  - Body: `JSON.stringify({ model: llmModel, messages: [{ role: 'system', content: SYSTEM_PROMPT }, { role: 'user', content: userPrompt }] })`
- Check `response.ok`: if not, `const body = await response.text()`, log error with status code and body hint about models:read permission for 401/403, `process.exit(1)`
- Parse response: `const data = await response.json()`, `const responseText = data.choices[0].message.content`
- Validate non-empty: if `!responseText?.trim()`, log error and `process.exit(1)`
- Get expected folder paths (normalized posix) from folders[] — use the same paths embedded in the prompt
- Call `parseResponse(responseText, expectedFolderPaths)` — any error propagates (fail hard)
- For each entry in the Map: find the corresponding outputPath from generatedPaths, `writeFileSync(outputPath, content, 'utf8')`
- Log each write: `console.log(\`  Writing LLM output for \${folderPath}...\`)`
- Log summary: `console.log(\`\\n  Generated \${generatedPaths.length} files (LLM-enriched).\\n\`)`

**401/403 error messaging**: When `response.status === 401 || response.status === 403`, add a line to stderr: "Ensure your GITHUB_TOKEN has the `models:read` permission. For fine-grained PATs, add the Models (read-only) permission."

Do NOT add timeout handling (user explicitly chose no timeout).
Do NOT add streaming (locked against in RESEARCH.md anti-patterns).
Do NOT add silent fallback to static (fail-hard is the locked behavior).
